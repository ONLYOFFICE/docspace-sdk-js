# Contributing

Thanks for helping with the ONLYOFFICE Apps Embed SDK. This page covers the toolchain, the branch flow and the release process. Conventions for the code and the documentation comments are in [AGENTS.md](./AGENTS.md) (written for coding agents, valid for humans too) and [docs-generation.md](./docs-generation.md).

## Requirements

- Node.js 24.15 or later.
- pnpm 12. The version is pinned in `package.json` → `packageManager`: pnpm 11 or newer switches to it automatically, pnpm 10 fails with `ENOEXEC` and must be upgraded (`npm install -g pnpm@latest`).

## Setup and checks

```bash
pnpm install
pnpm lint        # ESLint
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest (jsdom)
pnpm build       # dist/: esm, cjs, api.js, .d.ts
pnpm run docs    # API reference → docs/ (must finish without warnings)
```

CI runs the same commands plus a package-contents check, a link check of this file and the README, and `pnpm audit`.

## Making a change

1. Branch from `develop`; pull requests target `develop`. `master` receives releases only.
2. Follow the Definition of done in [AGENTS.md](./AGENTS.md#definition-of-done). For a new config field, instance method or mode, walk through the matching checklist in `.claude/skills/` — the `SKILL.md` files are plain Markdown.
3. Add a line to `CHANGELOG.md` under the current version heading. The release workflow builds the GitHub Release text from that section.
4. Public symbols need JSDoc in the style described in `docs-generation.md`; run `pnpm run docs` and fix every warning at the source (the comment or a `tools/` script), never in `docs/`.
5. Keep the SDK transport-only: a new method must be implemented by the ONLYOFFICE Apps client before it can work here, and the minimum portal version belongs in the pull request description.

## Tests

vitest with jsdom, globals enabled, files in `tests/`. There is no real iframe or postMessage in tests: the DOM is simulated and replies from the frame are injected as `MessageEvent`s. Use the helpers of the existing suites (`makeConfig`, `setupTarget` in `tests/instance.test.ts`) rather than new scaffolding.

## Documentation

`docs/` is generated by `pnpm run docs` and gitignored. The reference is published on [api.onlyoffice.com](https://api.onlyoffice.com/docspace/javascript-sdk/usage-sdk/) by the documentation site team; `pnpm run docs:sync` is their step and expects the site repository checked out next to this one. Contributors only need `pnpm run docs` to pass: fix warnings at the source, never edit the output.

## Releases

1. Set the new version in `package.json` and add a `## x.y.z` section at the top of `CHANGELOG.md`.
2. Merge `develop` into `master`. `create-tag.yml` reads the first version in `CHANGELOG.md` and pushes the tag `vx.y.z`.
3. `release.yml` builds the package, publishes it to npm with provenance and creates the GitHub Release from the CHANGELOG section.
4. After publishing: regenerate the reference from the tag for the site team, trigger a re-index of the repository on [Context7](https://context7.com/add-library), release the matching `@onlyoffice/docspace-react`, which bundles its own copy of the SDK, and update the `embed-sdk` skill in the `agent-skills` repository (`sync-sources --set-version`, `sync-sdk --check`) so its pinned version and validator follow the release.
